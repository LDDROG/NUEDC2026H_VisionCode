设计哲学

  • 传输无关：nanoMODBUS 核心库通过 nmbs_platform_conf 的 read/write 函数指针与硬件解耦，可适配任何串口/IP 实现。
  • ISR → 队列 → 协议：ISR 级回调只做数据搬运（写入环形队列），协议层从队列阻塞读取，避免 ISR 中做复杂处理。
  • 单一实例：当前移植为单服务端/单客户端设计（全局 g_port_ctx），不支持多总线。

2.2 环形队列 (nmbs_ring_queue)

文件行数说明
nmbs_ring_queue.h78队列结构体和 API 声明
nmbs_ring_queue.c138基于位掩码的环形队列实现

设计特点

  • 2 的幂约束：容量必须为 2 的幂，使用 head & mask 代替取模运算，效率极高。
  • 单生产者-单消费者：head 由 ISR（生产者）写入，tail 由协议层（消费者）写入。无锁设计在 SPSC 场景下安全。
  • 容量：当前配置 NMBS_PORT_RTU_RX_RING_SIZE = 512 字节，足够缓冲多帧 Modbus RTU 数据。

5. 缺陷与漏洞清单

#层级严重度描述位置
1 Port 高 单一全局实例限制。g_port_ctx 和 g_server 是全局静态变量，不支持多个 nanoMODBUS 实例同时运行。如果未来需要多总线或主从共存，需要重构为实例化设计。 port.c:21-23
2 Port 中 客户端发送前清空接收队列。write_serial() 在客户端模式下调用 NMBSRingQueueReset()，如果队列中已有未处理的应答数据会被丢弃。在总线竞争场景下可能丢失数据。 port.c:457
3 Port 中 阻塞式发送。write_serial() 使用 USART_TRANSFER_BLOCKING 模式发送，会长时间占用 CPU。在高负载场景下可能影响其他任务调度（尤其 FreeRTOS 环境）。 port.c:465
4 Port 中 回调链只保存一层。NMBSPortAttachCallback() 只保存前一个回调（chained_callback），如果 USART 实例已被其他模块挂载回调，旧回调会丢失。 port.c:287-301
5 Port 中 NMBSPortWaitUsartReady 超时精度。使用 TimeGetBootMs() 做毫秒级超时判断，但 byte_timeout_ms 参数名义上是毫秒，实际精度受限于 TimeGetBootMs() 的实现（除以 1000）。 port.c:362-394
6 RingQueue 低 PushBytes/PopBytes 逐字节循环。批量操作实际上是单字节循环，效率低于 memcpy + 批量指针移动。在高波特率场景下可能成为瓶颈。 nmbs_ring_queue.c:99-137
7 RingQueue 低 head/tail 无符号溢出。head 和 tail 是 uint16_t，持续递增最终会溢出回 0。但由于使用 head - tail 计算可用量（无符号减法自动处理溢出），实际不会出错——这是正确的设计。 nmbs_ring_queue.h:11
8 Port 低 server_write_single_coil 参数。value 参数为 bool 类型，但 Modbus 规范中 FC05 的线圈值为 0xFF00（ON）或 0x0000（OFF）。nanoMODBUS 核心库已处理此转换，但 port 层的 server_write_single_coil 实现中 uint8_t coil = value ? 0x01U : 0x00U 写入位图时只设置了 bit 0，而非完整的 0xFF/0x00 语义——这在位图操作中是正确的。 port.c:528-532
9 Port 中 无 RTU 地址校验。nmbs_server_init() 使用 server->id 作为 RTU 地址，但 server 结构体的 id 字段由调用者设置，无范围校验（Modbus RTU 地址有效范围 1-247，0 为广播）。 port.c:207
10 Port 低 日志格式字符串。LOGWARNING("[nmbs_port] RX queue overflow, dropped=%u", ...) 使用 %u 格式打印 uint32_t，在 32 位平台上正确，但应使用 %lu 或 PRIu32 以保证可移植性。 port.c:277

7. 改进建议

高优先级

  1. 实例化重构：将 g_port_ctx / g_server 改为通过 nmbs_t 的用户数据指针（nmbs_set_platform_arg()）传递，支持多实例。
  2. RTU 地址校验：在 nmbs_server_init() 中检查 server->id 范围（1-247）。
  3. DMA 发送：write_serial() 改用 DMA 发送模式，避免阻塞 CPU。

中优先级

  1. 回调链扩展：支持多层回调链表（而非单个 chained_callback），允许多协议栈共存。
  2. 缺失回调：根据业务需求实现 FC02/FC04 等回调，或在 nmbs_callbacks_create() 中显式禁用（通过 NMBS_SERVER_READ_DISCRETE_INPUTS_DISABLED 宏）。
  3. 压力测试：在高波特率（115200+）和高负载下测试环形队列是否溢出。

低优先级

  1. 批量操作优化：NMBSRingQueuePushBytes 使用 memcpy + 指针移动替代逐字节循环。
  2. 日志格式：统一使用 PRIu32 等固定宽度格式宏。
  3. 文档：补充移植层的 API 使用说明和注意事项。
