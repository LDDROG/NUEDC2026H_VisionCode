1. 整体架构

设计模式

BSP 层采用经典的 注册-回调 (Register & Callback) 模式，与 RoboMaster INF 工程（即"步兵电控"框架）高度同源。每个外设模块提供：

  1. XXXInstance — 运行时实例结构体（由模块持有）
  2. XXX_Init_Config_s — 初始化配置结构体（由调用者填充）
  3. XXXRegister() — 注册函数，返回实例指针
  4. 操作 API（发送/接收/设置等）
  5. 中断分发函数（统一 IRQ Handler → 查表 → 回调）

架构图

┌─────────────────────────────────────────────────────────┐ │ 应用层 (main) │ │ nmbs_server_poll / 业务逻辑 │ ├──────────┬──────────┬──────────┬──────────┬─────────────┤ │ bsp_usart│ bsp_spi │ bsp_iic │ bsp_can │ bsp_gpio │ │ │ │ │ │ bsp_pwm │ │ │ │ │ │ bsp_time │ │ │ │ │ │ bsp_log │ ├──────────┴──────────┴──────────┴──────────┴─────────────┤ │ TI MSPM0 DriverLib (DL_xxx) │ ├─────────────────────────────────────────────────────────┤ │ MSPM0G3507 Hardware Registers │ └─────────────────────────────────────────────────────────┘

BSP 层对上提供与 STM32 HAL 风格兼容的 API（保留了 HAL_xxx_Callback 命名），对下调用 TI DriverLib（DL_xxx）。中间通过类型别名（typedef UART_Regs UART_HandleTypeDef 等）实现 API 兼容。

3. 各模块详细分析

3.1 USART 模块 已完成

功能概述

支持 4 路 UART（UART0-3），每路独立 DMA/中断接收，不定长帧判断（帧间隙超时），三种发送模式（阻塞/IT/DMA）。ISR 回调链式分发。

架构亮点

  • 帧间隙判帧：通过 USARTServiceTickUs() 由外部 1ms 定时器驱动，累加 stable_ticks_us，超过 rx_frame_gap_us（默认 2000μs）即判定一帧结束——这是对 STM32 IDLE 中断的软件替代方案，适配 MSPM0 无 IDLE 中断的特性。
  • DMA + FIFO 补齐：USARTDrainFifoTail() 在帧结束时把 RX FIFO 中残余字节补齐到 recv_buff，解决 DMA 搬运与 FIFO 之间的时序差。
  • 回调链：NMBSPortAttachCallback() 保存旧回调并链式调用，允许多层协议栈共存。
  • 统一 IRQ 分发：USARTHandleUARTIRQ() 通过 DL_UART_getPendingInterrupt() 区分 TX/RX/各种错误，分发到对应处理函数。

从 STM32 移植的痕迹

  • 保留 HAL_UARTEx_RxEventCallback() / HAL_UART_ErrorCallback() 命名（实际是 MSPM0 ISR 直接调用）
  • typedef UART_Regs UART_HandleTypeDef 类型别名
  • 注释中仍引用 STM32 HAL 的 DMA 半传输中断设计（__HAL_DMA_DISABLE_IT 注释）

3.2 GPIO 模块 已完成

功能概述

支持 10 个 GPIO 实例注册，外部中断回调分发（GROUP1_IRQHandler），Toggle/Set/Reset/Read 四个基础操作。

注意点

  • GPIO_Pin 使用 int 类型存储 bitmask，与 MSPM0 DL 库的 uint32_t 不一致，存在隐式截断风险。
  • GROUP1_IRQHandler 同时处理 GPIOA 和 GPIOB，但 MSPM0G3507 可能还有 GPIOC/GPIOD，需确认中断分组。
  • 使用 malloc() 分配实例，嵌入式场景建议改为静态池。

3.3 SPI 模块 已完成

功能概述

支持 2 路 SPI（SPI0/SPI1），每路最多 4 个从机。三种工作模式：阻塞、IT、DMA。支持 CS 共享状态管理。

架构亮点

  • CS 共享总线状态：同一 SPI 总线上的多个从机通过 cs_pin_state 指针共享总线占用状态，避免冲突。
  • IT 模式突发发送：每次 TX_EMPTY 中断最多填 3 字节（SPI_IT_TX_BURST_MAX），平衡 FIFO 深度和中断频率。
  • DMA 纯接收：发送通道使用固定 0xFF dummy 数据提供时钟（s_spi_dma_dummy_tx）。

注意点

  • SPIDeviceOnGoing 是全局可见的 uint8_t 数组，非原子操作，中断上下文访问时存在竞态。
  • IT 模式下 it_length 为 uint8_t，最大传输长度 255 字节。

3.4 I2C 模块 已完成

功能概述

支持 2 路 I2C（I2C0/I2C1），最多 8 个从机。三种工作模式 + 序列传输（HOLDON/RELEASE）。支持 Mem 读写（8/16 位地址）。

架构亮点

  • DMA 通道分时复用：I2C 是半双工，TX/RX 共享同一 DMA 通道，通过 DL_DMA_setTrigger() 动态切换触发源。
  • 序列传输：IIC_SEQ_HOLDON 模式下不发送 STOP，保持总线占有权，用于复合传输（如先写地址再读数据）。
  • 完善的错误处理：iic_finalize_error() 清空 FIFO 并重置状态。

注意点

  • IICAccessMem() 中 16 位地址的字节序处理 addr_buf[(uint8_t)(2U - addr_len + i)] 逻辑需验证——当 mem8bit_flag=1（8 位地址）时，addr_len=1，取 addr_buf[1]（低字节），这是正确的。
  • 阻塞等待使用 IIC_BUSY_WAIT_LIMIT = 2000000 次循环，无真实超时机制（依赖 CPU 主频）。

3.5 CAN 模块 未移植到 MSPM0

状态说明

⚠ 此模块尚未从 STM32 移植到 MSPM0。

  • 代码中仍使用 STM32 HAL 的 FDCAN_HandleTypeDef、CAN_HandleTypeDef、HAL_FDCAN_xxx、HAL_CAN_xxx 等 API。
  • 头文件引用 "fdcan.h" / "can.h"，这是 STM32 CubeMX 生成的头文件。
  • MSPM0G3507 不带 CAN 外设（MSPM0 系列无硬件 CAN），此模块需要替换为软件 CAN（如 MCP2515 SPI-CAN）或移除。
  • 代码中大量 while(1) 死循环无日志输出（如 CANAddFilter 中的错误处理），移植后需改进。

3.6 PWM 模块 已完成

功能概述

支持 16 个 PWM 实例，动态设置周期和占空比，DMA 传输接口（未实现）。

注意点

  • PWMStartDMA() 函数体为空（只有注释掉的 HAL 调用），DMA PWM 功能未实现。
  • 使用 float 类型存储周期和占空比，嵌入式场景建议用定点数避免 FPU 依赖。
  • 周期计算依赖 CPUCLK_FREQ 宏和 DL_Timer_getClockConfig()，需确认时钟树配置。

3.7 Time 模块 已完成

功能概述

基于 TIMG12 的 32 位自由运行定时器，1μs 精度。提供全局时间戳、标定/偏移计算、阻塞延时。

注意点

  • TimeInit() 未配置预分频器（直接 DL_TimerG_setLoadValue + DL_TimerG_startCounter），实际精度取决于 SysConfig 中的配置。
  • TimeRegister() 使用 pvPortMalloc()（FreeRTOS 堆），但 TimeInit() 不依赖 FreeRTOS。
  • TimeGetBootMs() 通过 TimeGetTick() / 1000 实现，如果 tick 精度不是 1μs 则毫秒值不准。
  • TimeGetTickDelta() 与 TimeGetElapsedUs() 完全相同，属于冗余函数。

3.8 Log 模块 已完成

功能概述

基于 SEGGER RTT 的日志系统，支持三级日志（INFO/WARNING/ERROR），支持颜色输出。通过 DISABLE_LOG_SYSTEM 宏可在 Release 版本关闭。

注意点

  • Float2Str() 使用 sprintf() 且无缓冲区长度检查，存在溢出风险。
  • 不支持浮点格式化输出（RTT 限制），需要手动调用 Float2Str() 转换。

6. 改进建议

高优先级

  1. CAN 模块决策：MSPM0G3507 无硬件 CAN，需决定是否使用外部 SPI-CAN 芯片（如 MCP2515）并重写 BSP，或直接移除此模块。
  2. 竞态修复：SPI 的 SPIDeviceOnGoing 改为 volatile 并在关键段使用 __disable_irq() / __enable_irq() 保护，或改用原子操作。
  3. Float2Str 安全性：增加缓冲区长度参数，或改用 snprintf()。

中优先级

  1. 统一内存分配：所有模块统一使用静态池（如 USART 的做法）或统一使用 malloc，并在注册失败时提供明确错误码。
  2. PWM DMA 实现：实现 PWMStartDMA() 或删除该接口避免误导。
  3. 注释清理：移除 STM32 HAL 相关注释，补充 MSPM0 专用说明。

低优先级

  1. Time 模块：确认 SysConfig 中 TIMG12 预分频配置，或在 TimeInit() 中显式配置。
  2. 冗余函数：删除或标记 TimeGetTickDelta()。
  3. GPIO 类型：GPIO_Pin 改为 uint32_t 与 DL 库保持一致。
